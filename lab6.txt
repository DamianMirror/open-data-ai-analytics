Ознайомлення із практиками GitOps
Умови завершення
Використання GitOps для автоматизованого розгортання застосунку
Мета роботи
Ознайомитися з практикою GitOps та реалізувати автоматизоване розгортання застосунку в Kubernetes-середовище на основі змін у GitHub-репозиторії.

Теоретичні відомості
GitOps — це підхід до розгортання та керування застосунками, за якого бажаний стан системи описується у Git-репозиторії, а спеціальний агент у кластері автоматично приводить реальний стан до того, що збережено в Git.

Основні ідеї GitOps
Git є джерелом істини для конфігурації;

інфраструктура і застосунок описуються декларативно;

зміни виконуються через commit і push;

розгортання відбувається автоматично;

rollback можна виконати через повернення до попередньої версії в Git.

У цій роботі для реалізації GitOps використовується Argo CD.

Постановка завдання
У попередніх лабораторних роботах студенти:

створили модульний проєкт;

реалізували CI через GitHub Actions;

підготували Docker-образи;

виконали хмарне розгортання в Azure;

налаштували моніторинг через Prometheus і Grafana.

У цій лабораторній роботі необхідно
реалізувати GitOps-підхід для вже створеного застосунку, щоб оновлення виконувалося автоматично після зміни конфігурації у GitHub.

Сценарій виконання роботи
У лабораторній використовується один рівень складності:

Azure Linux VM

k3s як полегшений Kubernetes

Argo CD для GitOps

GitHub repository з Kubernetes YAML-файлами

Цей варіант є достатньо практичним, але не перевантаженим зайвою складністю.

Завдання лабораторної роботи
Необхідно виконати такі дії:
1. Підготувати GitOps-структуру репозиторію
У GitHub-репозиторії створити папку, наприклад gitops/, у якій розмістити Kubernetes-конфігурації застосунку:

namespace.yaml

deployment.yaml

service.yaml

application.yaml для Argo CD

Приклад структури:

gitops/
  app/
    namespace.yaml
    deployment.yaml
    service.yaml
  argocd/
    application.yaml
2. Підготувати Kubernetes-середовище
На Azure Linux VM:

встановити k3s;

перевірити роботу кластера;

переконатися, що команда kubectl get nodes повертає активний вузол.

3. Встановити Argo CD
У кластері необхідно:

створити namespace argocd;

встановити Argo CD;

перевірити, що pod-и Argo CD працюють;

отримати доступ до веб-інтерфейсу Argo CD через браузер.

4. Підготувати опис застосунку
Створити Kubernetes manifest-файли для веб-застосунку, який був створений у попередніх лабораторних роботах.

Deployment повинен містити:

назву застосунку;

Docker-образ;

кількість реплік;

відкритий порт контейнера;

labels і selectors.

Service повинен забезпечувати доступ до застосунку в кластері.

5. Підключити GitHub-репозиторій до Argo CD
Налаштувати в Argo CD об’єкт Application, який:

підключається до GitHub-репозиторію;

використовує потрібну гілку;

читає конфігурацію з папки gitops/app;

виконує розгортання у вибраний namespace;

має ввімкнену автоматичну синхронізацію.

6. Виконати перше розгортання
Після підключення Argo CD потрібно:

дочекатися стану Synced;

перевірити, що застосунок створений у кластері;

відкрити застосунок у браузері.

7. Продемонструвати автоматичне оновлення
У GitHub-репозиторії виконати одну зміну, наприклад:

змінити кількість реплік;

змінити тег образу;

змінити змінну середовища;

змінити текст у веб-інтерфейсі.

Після commit і push потрібно перевірити, що:

Argo CD виявив зміну;

синхронізація відбулася автоматично;

зміна застосувалася без ручного запуску kubectl apply.

8. Продемонструвати rollback
Повернутися до попереднього стану за допомогою Git:

скасувати останню зміну;

або повернути попередній commit;

перевірити, що Argo CD автоматично повернув застосунок до попередньої конфігурації.

9. Перевірити сумісність із моніторингом
Після GitOps-оновлення потрібно впевнитися, що:

застосунок доступний;

Prometheus продовжує збирати метрики;

Grafana залишається доступною;

створений у попередній роботі дашборд працює.

Очікуваний результат
У результаті виконання лабораторної роботи студент повинен отримати:

Kubernetes-кластер на базі k3s в Azure;

встановлений Argo CD;

GitHub-репозиторій із декларативним описом застосунку;

автоматичне розгортання застосунку через GitOps;

підтвердження автоматичного оновлення після зміни в Git;

підтвердження rollback;

працездатний моніторинг через Prometheus і Grafana.

скріншоти:
